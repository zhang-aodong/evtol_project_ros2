# 检测延迟与侧向来机避障修复（2026-11-14）

## 根因

旧实验 `ros_20261114_084304_de7fd2` 有 5455 个已评分的检测帧，全部超过实时证据时限。检测到达年龄中位数 760.5 ms，90 分位 990 ms。模型并非没有输出：几何匹配目标次为 5871，但过时结果不能计为实时检测成功。

同时，当前用户相机水平视场只有 70°，侧后方目标不能靠这台前视相机得到语义；原全周导航雷达只检查静态点，没有估计侧向来机速度。原局部速度规划器在悬停时只考虑停车，任务完成后的零速逻辑还会覆盖避让指令。

## 实现

1. 相机采集仍使用已有 UE 共享内存。新增 `/drone1/camera/rgb/image_realtime`：在原始 RGB/真值语义归档重排之前发布当前 RGB，保持真实采集时间戳，跳过倒序完成帧，并缩放到模型输入尺寸。模型默认订阅此话题；归档原图、真值语义流及其频率配置保留。控制分支允许丢弃旧帧，以保持实时性。
2. 视觉输入和融合等待队列使用 latest-only 策略。模型仍使用原 GPU 模型，不读取真值语义图、不使用障碍机 ID。
3. 新增 `evtol_targeting.lidar_obstacles` 节点，使用全周导航雷达和采集时刻本机位姿，在 ENU 中聚类、关联和估计速度，发布 `/drone1/perception/lidar_obstacles`。来源为 `lidar_cluster_unclassified`，类别为 0，不冒称视觉识别的无人机。
4. 原始全周点云始终参加静态间距与刹停检查。未知小点簇经过连续运动确认后才加入动态 CPA 预测，避免静态碎点的初始速度不确定性产生巨大的虚假运动包络。
5. 前视视觉 + 激光深度融合结果继续参与避障。小无人机和单人目标的异常大尺寸簇会被过滤，以防建筑/地面误分割形成巨大动态障碍；这些环境点仍由原始雷达保护。
6. 发生预测交会时，悬停也会生成避让候选。若名义平滑速度都不安全，会检查速度上限内的逃逸指令；仍使用实测速度、反应延迟和配置加速度计算 CPA，并通过原始点云间距检查。无安全候选时明确停车，不保证所有不可避碰场景都能化解。
7. 任务完成且本机仍处于新鲜的 `flying` 状态时允许悬停避让；停机、着陆、失效状态不放行。避让后停在安全的新位置，当前不会自动返回已完成的末航点。

## 配置

`config/targeting.yaml` 新增 `lidar_obstacles`。默认 10 Hz、30 m、聚类半径 0.8 m、至少 3 点、最大点簇跨度 4 m、扫描窗 0.12 s、最大轨迹年龄 0.4 s。运动确认默认至少 4 个观测、时间跨度 0.35 s，回归窗口 0.8 s，最小速度 0.5 m/s，位置拟合残差不超过 0.25 m，速度需超过 2 倍估计标准差。

`min_height_enu_m: 0.35` 是当前平坦起飞场景的明确 ENU 高度门限，只用于空中小目标运动分支。它假设起点附近地面位于 ENU 高度约 0；不是通用地面分割。换成山地、高架平台或低空障碍场景时需降低该门限（允许负数）。门限不作用于原始静态防撞点云。

`detection.max_drone_extent_m: 4.0` 与 `max_pedestrian_extent_m: 3.0` 分别限制单个无人机、单人语义点簇跨度。更大的目标或人群应另设类别/聚类策略并调参，不能直接按上述单体假设评估。

最大动态目标预算为 128，超预算会明确诊断并安全停车，不静默截掉近障碍。`lidar_obstacles.enabled: false` 可关闭新运动分支，原始全周静态防撞仍保留。

## Foxglove 与使用

结束旧实验，重启管理程序，再重新启动 UE 和仿真：

```powershell
cd D:\ZAD_Files\evtol_files\evtol_project_ros2
.\scripts\start_console.ps1 -NoBrowser
```

Foxglove 使用原来的连接地址；重载应用以加载更新后的 EVTOL Simulation Console 扩展。避障实验页面新增“检测链路与侧向保护”：推理耗时、结果年龄、视觉无人机像素、未分类雷达点簇、运动确认数、参与避障数、几何匹配目标次、超时帧数。点簇数不等于真实障碍机数。

3D 面板坐标系用 `map_enu`，可加入：

- `/drone1/perception/markers`：视觉融合轨迹。
- `/drone1/perception/lidar_obstacle_markers`：蓝青色未分类雷达点簇，包含未确认轨迹。
- `/evaluation/markers`：独立真值和评估范围，仅用于评估显示。
- `/drone1/safety/risks`：`source` 区分 `vision_lidar` 与 `lidar_only`，附 CPA、包络及标准差。

雷达独立避让不计入视觉检测成功率；过时结果不回填成功率。模型权重和用户当前配置/航点未改。70° 前视相机仍有侧后方视觉盲区；可在面板将水平视场改为 100° 后保存并重启 UE，代价是同分辨率下目标像素变少。真正的全向视觉需多相机及对应标定、推理设计。

## 真实验证与边界

使用隔离 ROS 域 222、真实 UE、真实模型，控制不读取障碍机真值；测试观察器使用独立真值核对预警和间距。结束后清理自有进程，保留用户配置。

- 32 机短期并发回归：`reports/perception_live_32.json`。32/32 障碍机就绪，本机成功起飞并前进至约 ENU 北向 13 m；融合结果年龄中位数 102 ms、90 分位 126 ms；1187 个已评分检测帧中超时 0，几何匹配目标次 525。采样有范围内真实 3 架、检出 2 架，以及真实 4 架、检出 1 架。有效计分目标时刻累计召回约 42.5%（339/797，含视觉盲区），不能用某帧最高召回 100% 宣称总体达到 100%。该测试验证及时检出与并发功能，不代表完整航线和高成功率验收。
- 稳定悬停侧向穿越：`reports/perception_live_side.json`。本机到达约 10 m 后，侧机从 ENU `[20,0,10]` 以 2 m/s 飞向 `[-20,0,10]`；观察器要求雷达预警轨迹与该侧机真值相距小于 2 m。正式安装包复测获得对应预警并执行逃逸，采样最小中心距离约 3.23 m，碰撞计数 0；视觉召回为 0（目标在侧方），不是视觉全向检出成功。暂存代码的前一次交会最小距离约 3.27 m。

汇总报告 `reports/perception_verification_summary.json` 同时给出了计数口径：32 机场景全范围为 339/797（42.5%），相机与激光共同视场内为 318/540（58.9%），均为有效目标时刻累计值。共同视场只是几何可见条件，不保证没有遮挡或足够像素，模型检测仍有改进空间。真值不完整的时刻单列无效，不作为成功。

147 项 Python 回归、Foxglove TypeScript 检查和 DOM 操作测试通过；6 个 ROS 包已重新编译。另核对 16 个安装文件的哈希和模块导入路径，并在正式安装包上通过 8 项关键回归，报告见 `reports/perception_install_verification.json`。旧文件备份位于 `backups/perception_side_20261114_095332`。

单次无碰撞不构成任意方向、任意速度、遮挡/多机包围下的保证。长期召回和预警成功率仍需固定种子、多次试验、不同角度/距离/速度及遮挡场景统计；模型的远小目标和域适配能力需要进一步用标注数据验证、训练。现有修改解决主要实时链路和侧向控制缺口，不伪造语义检测或真值控制。
