# 融合动态避障与范围检测实验

实现日期：2026-11-14。此版本完成代码与离线/ROS 消息测试，实际 UE 多机飞行、32/64 机吞吐和协议级预警性能需通过指定场景实测。本次安装不会自动起飞。

## 启动与更新

1. 先用原控制台停止 ROS 和 UE，退出原管理终端；若关闭卡住，用现有“强制结束 ROS + UE”。不要在同一仿真端口保留两个采集栈。
2. 在 `evtol_project_ros2` 运行 `./scripts/start_console.ps1 -NoBrowser`，重载 Foxglove，连接终端打印的 WebSocket 地址，打开 **EVTOL Simulation Console**。
3. 已打开的旧面板需重载才会更新。脚本会安装打包好的扩展。无需重新安装 ROS，也无需重编 UE 插件。
4. 旧版 console.local.json 自动迁移到版本 2 草稿：默认相机 FOV 70°、推理 960、评估 R=20 m、融合动态检查开启。原本航点/剖面、障碍航点和运行选择保留；第一次点击“校验并保存全部参数”后才持久化。**FOV 改变必须重启 UE，不能接入仍使用 35°的旧 UE。** 启动 ROS 会检查实际相机配置。
5. 先取消“执行飞行控制”验证采集和指标，再在停止 ROS 后启用执行。执行模式会等真实视觉推理就绪、所有障碍机完成起飞并经过首个实验航点后启动本机网关。

## 文件导入导出

顶部“从文件导入配置”选择 JSON，加载并校验为未保存草稿，不启动程序、不改变正在运行的实验。点击保存后下一次启动生效。

- “导出当前编辑配置”：校验草稿后下载全部参数。
- “导出已保存配置”：下载管理端已保存版本。
- “导出本次运行配置”：下载实际使用的不可变运行快照。
- 支持旧版本 1 升级；未知字段、无穷/NaN、重复机名、不合法尺寸或制动速度被拒绝。
- 直接从文件启动管理界面：`./scripts/start_console.ps1 -NoBrowser -Config ./config/experiments/crossing_4.json`。此命令保存已验证配置，仍需在面板手动启动 UE/ROS。运行开关由文件决定，导入前检查是否为观察模式。
- 换机后修改 UE 程序和工程路径，模型 Python 仍用现有 machine.local.json；实验文件保留全部面板参数。当前 JSON 包含机器绝对路径，不会自动打包 UE 地图/模型，也未自动合并另一台机器的路径别名。

## 实验页

可设置相机视场、推理尺寸、融合开关、动态包络/预测参数、范围、证据有效期、评估缓冲、首次检出时限、窗口及频率等。数组使用 JSON，例如 `[1,1,0.5]`。

当前成功率为 `正确一对一匹配数 / 球形范围内真实机数`。真实 10、检出 8、误检 1 时为 80%，不能把误检加入分子。无目标为 N/A；缺真值为不可评估；算法不输出且观测证据过期则记漏检。已有三维测量证据保持默认 0.3 s，预测发布不会刷新它。超过评估缓冲 0.4 s 的结果另记迟到，不能回填在线成绩。

“仅飞行时计分”默认开启：预置、起飞和等待阶段仍显示实时数量，但不加入累计成绩/进入事件；正式计分在网关报告 flying 时开始。观察模式网关处于 shadow，要测试感知需关闭该选项。此开关也支持从文件读写。进入范围 0.5 s 内实际收到有效结果算及时成功，稍后发现为迟检；退出 `R+2 m` 持续 1 s 后才形成下一次进入事件。

面板显示全周、共同视场、滑窗、累计和事件成功率。共同视场只是几何覆盖，不判断遮挡；单个前相机不能证明全向视觉感知。当前匹配用表面中心到机体原点的 3 m 几何门限，密集目标可能关联歧义；它不证明真实身份正确，正式验收应增加仅评估用的身份校核。

3D 面板：固定 frame=`map_enu`，添加 `/evaluation/markers`、`/drone1/perception/markers`、`/drone1/navigation/waypoint_path`、`/drone1/navigation/traveled_path`。蓝色半透明球表示 R，绿色真值框已检出、红色框漏检。真值只用于评估，控制算法不订阅真值目标。

## 话题与数据

新接口使用版本化 JSON，通过标准 `std_msgs/String` 发布，无需生成新 ROS 消息：

- `/evaluation/detection_metrics`：范围、计数、成功率、事件汇总、有效性与计分阶段。
- `/evaluation/target_matches`：逐独立测量的合法一对一匹配与误检。
- `/evaluation/encounter_events`：进入、及时成功、迟检、漏检、退出。
- `/evaluation/warning_metrics`：真值瞬时 CPA 风险诊断、算法多目标风险，以及配置了冻结风险标签时的事件级混淆矩阵。没有标签时，协议相关比率为 null，不用当前实际轨迹反向生成闭环风险标签。
- `/evaluation/markers`：真值、漏检与预警范围。
- `/drone1/safety/risks`：多目标风险、包络、融合新鲜度、拒绝目标数和动作原因。
- `/simulation/truth/status`：每机采样时间/括号宽度、采样跨度、完整性及自机碰撞信息；每架机的真实时间见目标 last_measurement_stamp。

控制台运行目录 `data/console_runs/ros_*` 保存 console.json、actors.yaml、targeting.yaml、simulation.yaml、airsim.json。评估在该目录的 evaluation/range_* 保存 metrics/matches/encounters/warnings JSONL 和 run_summary.json。旧几何误差报告仍保留。

离线复算：

```powershell
. ./scripts/activate.ps1
python ./scripts/summarize_experiment.py ./data/console_runs/ros_xxx/evaluation/range_xxx
```

输出 CSV 和 recomputed_summary.json。复算只使用正式计分历元。连续帧存在相关性，不能用历元数量宣称 <1% 的独立事件误差上界。强制杀进程可能来不及完成收尾，保留的 JSONL 可复算；run_summary 中 ended=false 表示未正常完成收尾。

## 生成多机场景

```powershell
. ./scripts/activate.ps1
python ./scripts/generate_experiment.py --count 4 --output ./config/experiments/crossing_4.json
python ./scripts/generate_experiment.py --count 32 --output ./config/experiments/crossing_32.json
```

生成不触发飞行，默认执行开关关闭，航点采用初始点 ENU。可导入面板进一步调整。支持 4/8/16/32/64；64 是配置容量上限，尚未验证 UE 实时运行。场景总机数与 R 内同时出现数不同；模板不保证任意地图可通行，检查建筑、地形、机间距后再执行。模板种子决定生成速度，保留原始 JSON 即可复现同一参数；不保证 UE 调度完全确定性。

## 避障实现与能力边界

`dynamic.py` 用融合轨迹位置、速度、协方差和尺寸下限膨胀障碍包络，对每个候选做执行延迟、限加速度过渡和 3 s 预测。每个线性分段用连续 CPA 检查，另膨胀曲率误差；最后实际速度再检查。几何保护继续独立工作。新目标、速度不可信目标保守扩大运动包络，不直接忽略；无安全候选则制动并报告原因，不能保证任意包围场景都有安全解。

局部 A* 在 Windows spawn 子进程运行，父进程不等待搜索；路线与目标版本、观测时刻绑定，过期不沿用。第一条路线生成前会等待；几何检查仍约束每个实际指令。视觉/融合失效时限速至默认 0.5 m/s，雷达/状态失效按原安全保护停车。测量重复不能增加跟踪 hits，预测协方差随时间增长。

多机真值采用最多 4 个独立 RPC 客户端受限并发，输出每机时间与完整性，不伪造同时采样。当前没有新增 UE 批量真值共享内存接口；若 32 机评估完整率/频率不够，应先实测定位瓶颈再扩展生产端。原始相机/雷达/IMU 共享内存采集方式保留。

## 冻结风险标签与正式预警统计

实验配置中的 `experiment.warning_events` 默认为 `[]`，可在实验页用 JSON 数组编辑或从文件读取。每项格式如下，时间相对本次正式计分开始：

```json
[
  {"id":"crossing_01","truth_id":1,"start_s":5,"end_s":10,"deadline_s":7,"risk":true},
  {"id":"safe_pass_01","truth_id":2,"start_s":5,"end_s":10,"deadline_s":7,"risk":false}
]
```

truth_id 是障碍配置顺序从 1 开始的评估身份（第一架通常为 Drone2），不等于算法 track_id。评估器根据实际检测配对关联预警，使用全量收到的多目标风险样本计分，不只取面板最后一次结果；未匹配的预警另计诊断数。正事件在 deadline 之前报警才计 TP，迟警计 FN 并另列 late；负事件中任何报警计 FP，完整无警计 TN。缺真值或风险链路失效的事件标记 unscorable，不当作 TN 通过。

事件窗口和 risk 必须来自预先冻结的参考轨迹/场景标注或独立旁路实验，在运行前配置。配置文件本身不能证明标签正确；不要根据闭环实际已经绕开的航迹重写标签。时间不同步、障碍机未按计划运行应使该运行失效。面板同时展示 Precision、Recall、漏警率、FPR、误报占比、待判和不可评估事件。该统计不自动提供协议级置信结论。

冻结场景的独立重复试验与置信区间、全套自动飞行批量验收和 32/64 机实飞成绩尚不能由本次离线结果替代。先以 4 机、1～2 m/s 验证，再逐级增加数量和速度。
