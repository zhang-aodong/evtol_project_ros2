# 未起飞与采集界面缺失：检查和修复记录

## 日志结论

`gateway.log` 已记录 arming、takeoff，之后约 60 秒报 `Safety-controlled takeoff timed out`。不是没有启动飞行控制。`safety.log` 反复出现 `Waiting for complete navigation LiDAR sweep`、`LiDAR acquisition age exceeds budget` 和 `LiDAR stale`，导致起飞速度指令反复归零。同期相机也有 `Camera completion exceeded reorder window`、目标真值有 `Incomplete target truth`，说明这次 32 架障碍机运行期间存在明显的数据时效问题。

原配置在本机的后台和可视化独立复测均能起飞，未稳定复现完全无法起飞；因此不能把这次故障归结为一个永久配置错误。实现中导航雷达按 FIFO 补发积压帧、避障 50 Hz 重复解码/合并 20 Hz 雷达、位姿/雷达订阅排队，均会在负载波动时增加时延。本次修复这些可确认的实现问题，并增强起飞前检查和诊断；没有放宽原有超时门限，也没有关闭避障。

Foxglove 缺少采集页的原因已明确：之前的采集代码、安装包和面板仍在暂存工程，正式 `src/install` 和本地 Foxglove 扩展都是旧版。本次已部署、编译并校验正式安装路径。

## 修改

- 导航雷达控制流读取共享内存最新帧，并统计跳过帧；原始传感器归档流保持独立。
- 避障的位姿/点云订阅仅保留最新待处理消息；缓存采集时刻位姿变换，按配置所需扫描跨度选择新近帧，减少重复处理。
- 避障计算从 50 Hz 调整为 20 Hz，与导航雷达和控制网关匹配。原传感器目标频率没有降低。
- 控制台等待导航扫描与位姿持续就绪后，才启动执行网关；不满足条件时明确报错且不解锁。
- `/drone1/mission/status` 增加 `safety_data`：位姿接收年龄、雷达接收年龄、采集年龄、扫描帧数、实际/要求时间跨度、计算耗时；`navigation_ready_s` 表示连续数据就绪时长。采集帧不足、过期、无可行避障速度仍会停止运动。
- 完整安装 `evtol_collection`，更新控制台后端、网页、Foxglove 扩展及教程。
