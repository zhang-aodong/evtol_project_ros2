## 详细日志

所有页面底部新增“实时操作与运行日志”，可以折叠，支持关键字／来源筛选、只看警告错误、自动滚动与导出。

- 按钮点击立即在界面留下记录；显示请求已接受、操作 ID、实际执行状态和最终成败。
- 耗时操作每 5 秒输出“执行中”，普通关闭会显示正在等哪个清理服务及其超时预算。
- ROS 子进程的输出会实时收集到日志区，错误与告警带来源，保留原始逐节点日志文件。
- 主机显示飞行阶段、任务原因、ENU 位置、三维地速；运动日志每 5 秒采样一次，避免高频刷屏。
- 障碍机发布 `/scenario/status`（`std_msgs/String`，JSON 内容），包括等待、解锁、起飞、飞往第几个航点、
  到达、悬停、取消、降落、停止及失败原因。行人也发布运动／停止／失败阶段。
- “监控 / 日志”页显示原始详细状态、障碍机状态和进程 PID／日志路径。过期数据会标明失效，
  不会用旧速度和高度冒充当前数据。

障碍机状态内的 `target_local_ned_m`、`measured_local_ned_m` 明确使用该车 AirSim 局部 NED，
测量位置在航点到达检查时更新，并非持续位置流；界面任务编辑仍使用主机初始点 ENU。

管理日志持久保存为 `reports/console_manager_*.jsonl`，界面底部显示本次实际路径。
内存只保存最近 500 条事件、每次状态传输最近 300 条；文件达到约 20 MB 时轮换保留上一份。
“导出当前日志”保存当前状态、最近后端事件和界面事件；完整历史请读取 JSONL 和逐节点日志。

## 强制结束

窗口顶部始终显示红色 **强制结束 ROS + UE** 按钮：

1. 即使正在启动或普通停止等待中，也可以点击。
2. 请求走独立线程，立即中断正常清理等待，并阻止尚未完成的启动继续创建节点。
3. 跳过悬停、逐架降落与 ROS 清理服务，并行结束本控制台持有的 ROS 和 UE 进程树。
4. 日志显示每个 PID 的结束结果；如果某个进程未能终止，操作显示失败并保留其条目供重试。
5. 管理程序、预览节点和 Foxglove 桥接保持运行，可以继续查看日志或重新启动 UE／实验。

强制结束只处理**当前管理程序启动并持有的进程**。手动启动的 UE、其他工程的 Python、外部 ROS
节点、旧管理程序的进程均不会按名称被批量结束。需要使用强制按钮管理 UE 时，请由此控制台启动它。
这是立即结束仿真，不保证降落或业务日志／录包完整收尾。正常停止仍保留原有清理语义。

在入口终端按 `Ctrl+C` 退出管理程序时，也会中断等待并结束自有 ROS／UE，不再等待 180 秒逐架清理。
若要完成正常降落清理，请先在界面点“停止 ROS”，完成后再退出终端。

## 本次排查与验证

最新运行日志中主机进入过 `flying`，并在关闭时报告 `stopped`。障碍机存在 takeoff 任务返回超时但
实际已稳定离地的告警；它不是“进程没有启动”的证据。旧关闭流程等待场景清理最多 180 秒，
而场景内部按车辆逐架降落，每架可等待 60 秒；同时旧终止流程逐个等待进程树。
这些等待发生时缺乏可见进度，容易表现为卡住；现已增加可见进度、可中断等待与并行终止。
旧版没有持久管理日志，无法仅凭现存节点日志确认每一次历史卡顿的确切位置。

验证结果：107 项 Python 回归通过；UI 强制按钮在 busy 状态仍可用；真实 Windows 自有进程终止与外部进程保留检查通过，
以及真实 Foxglove 服务抢占等待、ROS 场景状态传输与子进程树清理。
测试探针 `tests/probe_console_force.py` 使用独立 ROS 域和无害 Python 进程作为被管理对象，
不启动 UE、不解锁飞机，也不干扰当前运行中的仿真。结果见 `reports/console_force_probe.json`。
真实协议测试同时验证被管理进程的下一层子进程已经退出。本次未重新进行 Foxglove 桌面目视验收。

原剖面实飞超时与本次关闭功能是分别验证的；本修改没有宣布该飞行问题已经解决。
