# 架构与参考来源

参考根目录是 `D:\ZAD_Files\evtol_files\evtol_project`，本次选择其中 `airsim_realtime_uav`，因为该子工程同时具备 RGB/语义主动共享内存、原生 LiDAR、IMU/GPS、GNSS 和 5G-A。没有将相邻的 UE5 small city 两传感器实验与 UE4.27 机场参数混用。

| 新模块 | 参考实现或参数 | 改动 |
|---|---|---|
| `camera_ring.py` | `uav_sim/shared_memory_camera.py` | 保留源协议布局、读取 guard 校验 |
| `lidar_ring.py` | `uav_sim/lidar_shared_memory.py` | 保留原生 XYZ 环形协议 |
| `gnss_model.py` | `uav_sim/gnss_raw.py` | 保留观测公式和随机种子逻辑 |
| `radio_model.py` | `uav_sim/five_g_a.py` | 仅保留观测模型，移除 SciPy 定位求解器和旧 AirSim 客户端适配 |
| `source_parameters.yaml` | `config/default.yaml` | 提取语义/GNSS/5G-A、障碍机、行人和固定任务参数 |
| `backend.py` | `data_collector.py` 采集流程 | 重写为采集适配器，移除落盘、模型推理、总线、定位求解 |
| `rpc.py` | AirSim PythonClient `client.py` 的公开方法参数顺序 | 自包含 MessagePack 核心类型和同步 TCP RPC |
| `sensor_node.py` | 源采集种类和目标频率 | 标准 ROS 消息、独立进程、坐标转换、TF、诊断 |
| `evtol_scenario` | 源 `interference_drones`/`pedestrians`/`flight.fixed` | 可选场景生成进程；不运行 avoidance |

源工程的 `flight.mode=avoidance` 依赖感知/规划，不适合放入只生成数据的层。本次将场景运动放在单独节点，使用源 `fixed` 路径；后续避障算法以 ROS 消费者实现。之前其他目录的 300 m profile 任务不是本次参考子工程默认任务，没有静默将它覆盖到机场 10 m 固定轨迹。

当前仿真发布节点：

```text
UE/AirSim
├─ RGB + Semantic Windows ring → camera_sensor → Image + CameraInfo
├─ LiDAR Windows ring          → lidar_sensor  → PointCloud2
├─ IMU RPC                     → imu_sensor    → Imu
├─ GPS RPC + truth             → gnss_sensor   → NavSatFix + GnssObservations
├─ truth RPC + sim timestamp   → truth_sensor  → Odometry + TF + /clock
└─ truth + scene LoS           → radio_sensor  → FiveGObservations

scene scenario (optional) → AirSim actor/flight APIs

ROS topics → RViz2 / rosbag2 / future localization and mapping packages
```

保持原始帧，不做点云持久积累、运动补偿或建图。传感器发布者不订阅算法结果，也没有闭环控制职责。真值 TF 是可关闭的可视化辅助；业务状态管理/定位将有单独的 topic 与 TF 所有权。

当前限制：共享内存仅适用于原生 Windows 同一会话；真实 UE 频率由渲染/物理/插件决定；Python 消息序列化存在拷贝；本版不修改外部 UE 渲染/回读实现，使用已编译插件提供的主动流；双路 2K 必须另行性能验收；未增加 barometer/magnetometer 等源默认采集链路中没有的传感器；Actor ID 身份评估通道暂未迁移；多机器人可分别启动命名空间和 frame 名称，但全局 `/clock` 应只有一个发布权，当前默认实现面向 Drone1。
