# 控制 RPC 断线恢复

控制网关在起飞状态查询、速度控制、降落校验等 RPC 出现网络超时或断连时，进入 `recovering`，关闭旧连接，重连并重新申请 API 控制。恢复后先取消未完成的动作，使用 `moveByVelocityZ` 制动并保持当前高度，再恢复原飞行阶段。

- 不重发超时的速度指令，不重新解锁，不自动重放起飞/降落任务。
- 恢复后必须收到比恢复完成时更新的指令序号，并通过原有状态有效性、时钟、TTL 检查，才能继续飞行。
- 起飞恢复期间暂停计算起飞超时；航点任务在恢复期间暂停推进。
- 服务持续不可用时持续重试，可通过原有停止或强制结束按钮终止。
- 任务逻辑异常进入 `failsafe_hold` 持续定高；需要停止并重新启动任务，不自动继续任务。
- 普通停止请求悬停并保留 API 控制；只有按原有流程确认最终航点着地后才上锁并释放 API 控制。强制结束不保证悬停。
- 控制台不会因为网关正在恢复、AirSim 暂不可达且其他关键节点退出，就将恢复网关一同结束。

Foxglove `/drone1/control/flight_status` 包含 `phase`、`reason`、`rpc_recoveries`（恢复事件次数）、`rpc_last_error`（含具体 RPC 方法）。正常状态变化示例：`takeoff → recovering → takeoff → flying`。收到故障保持请求时，恢复后保持 `failsafe_hold`。

连接中断期间无法向 UE 下发保持指令，因此不能保证断线期间的物理高度。恢复策略避免主动释放控制权，连接恢复后才可确认定高成功。原有碰撞规划及定位策略不在本次修复范围内。

## 应用与验证

正在运行的 Python 进程不会加载修改后的代码。停止 ROS 任务和控制台，在项目根目录运行 `./scripts/build.ps1`，再使用 `./scripts/start_console.ps1 -NoBrowser` 启动控制台。无需重新编译 UE。

自动测试 `tests/test_gateway_rpc_recovery.py` 在独立 ROS domain 下通过故障注入覆盖起飞状态查询超时、速度控制超时、持续断连、重复定高超时、控制权申请回复丢失和恢复后指令更新。它不控制正在运行的 UE，实际飞行仍需重启后验证。
