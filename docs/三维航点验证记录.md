# 三维航点与避障验证记录

日期：2026-11-07。平台：本机 Windows 11、ROS 2 Jazzy、UE4.27/AirSim、SimpleFlight。验证对象为 `evtol_project_ros2`，不修改 UE 插件源码。

## 实现范围

任务按 ENU 三维航点的位置、速度与停留时间判定到达。全向导航雷达经既有共享内存采集，按采集姿态累计扫描；局部三维 A* 与速度安全层共同生成指令。末点为地面时，经降落区域检查、受监视下降、触地与静止确认后解除解锁并释放 API 控制。空中末点完成后悬停。

配置、命令和边界见 [三维航点飞行与避障](三维航点飞行与避障.md)。默认用户航点仍为 `[[0,0,3],[0,30,3],[0,30,0]]`，测试使用独立配置，不覆盖它。

## 真实静态绕障闭环

证据：`reports/navigation_obstacle_merged.json`；配置：`config/navigation_obstacle_validation.yaml`。导航雷达最终为 128 线、230400 点/秒、20 Hz，前向雷达保持原参数。为隔离本机 DDS 环境问题，本次所有验证节点使用 ROS 域 47。

在起点北侧 3 m、高 3 m 处生成 `EditorCube`，执行 `[[0,0,3],[0,6,3],[0,0,0]]`。实际轨迹向西绕行约 3.6 m，通过立方体侧面，继续到北侧航点，返回起点并降落。

| 指标 | 结果 |
| --- | --- |
| 最终任务状态 | `complete`，3 个航点完成 |
| 最终控制状态 | `landed`，API 已释放 |
| 活动航点阶段最小位置误差 | 0.3211 / 0.3087 / 0.1588 m |
| 导航雷达接收频率 | 20.001 Hz |
| 导航雷达最大接收间隔 | 0.1136 s |
| 观测窗口 | 110.62 s，包含启动等待 |
| 控制 waiting 到 landed | 约 85 s |

绕行过程中存在 4～7 点局部路径；计算预算超限时输出停车并重试。降落过程中出现短暂 `landing_paused`，数据恢复后继续，最终完成。最小误差只用于分析，任务到点还要求速度和停留时间满足条件。

碰撞信息仅在窗口前后读取，最后接触对象均为机场地面 `FbxScene_Airport_Model`，与正常起降接触相符。该记录没有持续记录每次碰撞事件，因此不能据此严格证明全程零碰撞。测试后已删除专用立方体、停止测试 ROS 节点，并确认主机地面静止、API 控制关闭。

## 补充验证与回归

短程起降最终记录为 `reports/navigation_touchdown_acceptance.json`，状态为 `complete` / `landed`。同一会话的前段记录 `navigation_landing_acceptance.json` 在下降中结束，不单独当作完整起降通过。

无障碍三维路径 `[[0,0,3],[2,3,4],[-2,1,2.5],[0,0,0]]` 已实测到达前三个空中点，误差约 0.15 / 0.29 / 0.24 m。该早期试验发生在最终降落修复前，不当作整条三维路径的完整通过记录。

最终执行 `scripts/build.ps1` 和 `python -m unittest discover -s tests -v`。回归涵盖三维方向、墙体绕行、不可达目标、规划预算、异步降落状态、传感器过期、扫描积累，以及降落返回成功但仍在空中时禁止解除解锁等分支。最终构建与回归日志保存于 `reports/navigation_final_build.log`、`reports/navigation_final_tests.log`，以日志结果为准。

## 未通过与适用边界

`reports/navigation_sensor_acceptance.json` 是较早的 460800 点/秒导航雷达配置下的 60 秒全传感器测试：实时比例约 0.50，IMU 约 85.8 Hz，整体未通过原实时比例及 IMU 100 Hz 验收。最终降到 230400 点/秒后已完成上述绕障闭环，但没有重新完成全量 60 秒传感器验收，不能宣称所有频率达标。真实时间戳与原验收阈值均保留。

当前采用局部点云规划与真值自身位姿，未实现全局建图/SLAM。支持任意三维方向的有效航点输入，不保证封闭区域、障碍内部或任意迷宫可达；目标占据、无路、超预算或数据不足时停车。动态目标具有 CPA 安全约束，本记录主要验证静态立方体，不代表任意动态障碍场景均通过验收。
