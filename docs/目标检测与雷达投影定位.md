# 目标检测与雷达投影定位（2026-11-19）

当前避障感知采用 YOLO26 无人机目标检测，不启动语义分割推理。定位仍依靠真实激光雷达深度，输出 ENU 目标测量和跟踪结果，继续供原有动态避障、安全限速、UE 三维框与实验评价使用。

## 数据链路

1. UE 的前、右、后、左、上、下六路 RGB 图像经共享内存同步读取。
2. 独立 GPU 模型进程批量检测六个视图，输出实例框、类别和置信度；ROS 进程不加载 PyTorch。
3. `detection_fusion` 将 NavigationLidar 实测点投影至对应相机，按检测框关联。小目标还可在检测框内请求有预算限制的 ROI 真实雷达射线；不是用框中心和真值推算距离。
4. 框内点按深度聚类，过滤地面、不合理尺寸及背景，选择有内部支持的紧凑前景簇。重叠框不能重复占用同一点；没有有效雷达深度时不输出三维目标。
5. 按采集时刻的本机位置、姿态和外参补偿，转换为以会话初始点为原点的 `map_enu`，再进行跨视图合并、跟踪、速度估计与避障。位置代表可见表面观测中心，存在与机体中心的偏差。

本机真值定位接口暂时保留；障碍机真值只供独立实验评分使用，不作为检测或融合输入。原始雷达几何避障仍工作，侧向目标也可由环视检测关联。旧语义实现文件为历史兼容保留，当前编排不运行它们；UE 语义真值和数据采集功能仍可用于制作训练集，和在线分割推理是不同功能。

## 模型与参数

已部署此前训练的单类别检测权重 `models/drone_detection.pt`，模型任务为 `detect`，模型类别 `0: drone` 映射为 ROS 标准类别 `6`。模型来源、校验值记录在 `models/drone_detection.json`。

SHA256：`dcb94c97609352313840809dd93b2f74034be9e43e191b3239afc942da919279`。

主要配置位于 `config/targeting.yaml`：

```yaml
model:
  task: detect
  weights: models/drone_detection.pt
  confidence: 0.25
  iou: 0.5
  max_det: 128
  class_map: {0: 6}
  device: '0'
surround:
  enabled: true
  weights: models/drone_detection.pt
  width: 768
  height: 768
  horizontal_fov_deg: 100.0
  imgsz: 1024
  max_hz: 8.0
  roi_lidar: true
  roi_prefetch: true
detection:
  box_min_lidar_points: 3
  box_roi_padding_px: 4
```

以上是配置节选，不要覆盖整个 YAML。`max_hz` 是推理调度上限，不等于已保证的发布频率。每视图 ROI 最多 640 条射线，六视图合计最多 3840 条；检测实例和跟踪都限制缓存大小和数据年龄。`min_mask_pixels` 等旧参数不再控制检测框定位。

两个权重配置均应指向真正的检测模型，不能填入分割权重。加载阶段会检查任务类型。`models/semantic_runtime` 只是现有 Ultralytics 运行库目录的历史名称，其同时支持检测；当前使用它不会加载语义模型。
