# 三维航点飞行与避障

配置入口为 `config/targeting.yaml`。航点使用无人机初始点为原点的 ENU：X 东、Y 北、Z 上，单位米；与机头朝向无关。代码入口为 `evtol_safety/navigation.py`、`node.py` 和 `gateway.py`。

## 启动

先结束已有实验并完成车辆清理。首次更新必须关闭旧 UE 仿真实例，用新 settings 重启；只重启 ROS 节点不能增加 UE 传感器。

```powershell
cd D:\ZAD_Files\evtol_files\evtol_project_ros2
.\scripts\build.ps1
.\scripts\start_ue.ps1
```

`start_ue.ps1` 默认使用 `src/evtol_simulation/config/airsim.navigation_2k.json`。手动启动 UE 时也必须使用这个文件。它保留原前向 Lidar1，额外增加 NavigationLidar：水平 360°、垂直 ±90°、30 m、128 线、230400 点/秒、20 Hz。两者分别通过 UE 现有共享内存接口采集，无须为这次修改重新编译 UE 插件。新配置使用 SimpleFlight 默认推荐的固定物理步长 `SteppableClock`；旧可变步长配置在本机场景出现姿态振荡。相机及雷达仍使用墙钟生产频率，话题时间戳来自仿真时钟。换机仍按原迁移文档配置 `config/machine.local.json`。

等待 UE 启动、无人机在地面静止后，另一个终端运行：

```powershell
.\scripts\start_experiment.ps1 -NewSession -Execute
# 需要同时启动行人和障碍机时加 -Actors
```

`-Execute` 才会控制主机；不加时为 shadow。`-NewSession` 在起飞前建立初始原点；同一会话重启时去掉它。不要在半空重建原点后，仍把 Z=0 当作地面。不要与旧 scenario_node 同时控制 Drone1。

## 航点配置

```yaml
mission:
  waypoints_enu_m: [[0.0, 0.0, 3.0], [0.0, 30.0, 3.0], [0.0, 30.0, 0.0]]
  speed_mps: 2.0
  tolerance_m: 0.35
  arrival_speed_mps: 0.3
  arrival_hold_s: 0.3
  takeoff_height_m: 1.5
  land_at_last: true
  landing_ground_z_m: 0.0
  landing_target_tolerance_m: 0.25
  landing_handoff_m: 1.2
  landing_surface_tolerance_m: 0.15
control:
  takeoff_on_start: true
```

其余已有配置保留；上面是相关字段片段。依次执行：受雷达保护的初始爬升、到 3 m、向北到 30 m、下降至末点上方的降落交接高度、监视降落、确认触地与静止后解除解锁并释放 API 控制。末点若是空中高度则悬停；`land_at_last: false` 时所有点均按精确三维航点处理。非末点不自动改成降落动作。

三维位置进入容差、速度低于阈值并保持指定时间后才切换下一点。可以配置东/西/南/北、上升、下降、斜向航点。已在空中的主机可以在同一原点会话中用 `takeoff_on_start: false` 从当前位置继续；应提供新的剩余航点列表，任务索引不会持久化恢复。

降落的 Z 值应对应无人机参考点触地时的 ENU 高度。`landing_ground_z_m` 用于识别末点是否为地面点，不会自动探测整张地图地形。不同高度的停机坪要相应配置。支撑面与落地区域未观测到或存在障碍时暂停降落。网关不会仅凭 AirSim 的成功布尔值在半空解除解锁。

## 避障与状态

全向雷达点云按采集时刻的机体姿态转换到 ENU。三维体素 A* 在当前局部范围内寻找绕行路径，每条边和简化后的路径都检查安全间距；50 Hz 速度保护继续检查制动距离、全部几何回波和动态目标 CPA。视觉语义定位沿用原前向雷达及模型。起飞和末段降落只对规定区域内、低于规定高度的支撑面作特殊处理。

固定步长下单帧可能只包含部分旋转，安全节点会按各帧的采集姿态合并最近扫描，积累足够旋转时间后才允许运动。`navigation_lidar.scan_window_s: 0.3` 为墙钟积累上限，`minimum_sweep_s: 0.04` 为帧间仿真时间跨度下限；采集年龄仍受 `safety.cloud_timeout_s` 约束。每帧坐标单独补偿，合并后保留体素中最近回波。未积累完整扫描时输出停车原因。

`navigation` 配置控制分辨率、规划半径、计算预算、安全间距、前视距离、位置增益和速度阻尼。可选的 `control.velocity_gains: {kp: [0.2, 0.2, 2.0], ki: [0.0, 0.0, 2.0], kd: [0.0, 0.0, 0.0]}` 通过 RPC 应用 AirSim 速度环增益；默认不覆盖底层增益。任务、避障和网关速度上限必须一致。

| 话题 | 用途 |
| --- | --- |
| `/drone1/navigation/lidar/points` | 独立全向避障点云，20 Hz，机体 FLU |
| `/drone1/navigation/path` | 当前局部三维规划路径，ENU |
| `/drone1/mission/status` | 航点索引、任务阶段、停车/规划原因，JSON String |
| `/drone1/control/flight_status` | 网关起飞、飞行、降落、完成或失败状态 |
| `/drone1/control/safe_velocity` | 实际执行的 ENU 速度指令 |

Foxglove 桥接已允许上述话题。3D 面板设为 `map_enu`，添加点云与 Path；RViz2 同样使用 `map_enu`，传感器话题选 Best Effort。JSON 状态用 Raw Messages 查看。

```powershell
. .\scripts\activate.ps1
ros2 topic echo /drone1/mission/status --qos-durability transient_local --full-length
python scripts\observe_navigation.py --seconds 120 --output reports\navigation_live.json
```

验收脚本只读话题和碰撞信息，输出实际轨迹、各点最小距离、雷达频率、任务阶段与原因。`config/navigation_validation.yaml` 是独立的短程三维测试航点。最小距离用于分析，正式到点仍以任务停稳判定为准；地面接触本身会更新 AirSim 碰撞时间戳，须区分正常落地和飞行中的障碍碰撞。

中止主机执行：

```powershell
ros2 service call /drone1/control/stop std_srvs/srv/Trigger '{}'
```

该服务取消任务、请求悬停并释放控制，不等于自动安全降落；空中中止后需要按场景接管或完成降落，再结束 launch。完成末点自动降落后可以结束 launch。已有 `stop_experiment.ps1` 仍只负责 shadow 且未启动 actors 的实验。

可重复的静态绕障实验（与默认航点分开，先确认无人机在地面）：

```powershell
. .\scripts\activate.ps1
python scripts\navigation_test_obstacle.py
.\scripts\start_experiment.ps1 -Config config\navigation_obstacle_validation.yaml -NewSession -Execute
```

在另一已激活且相同 ROS 域的终端运行 `python scripts\observe_navigation.py --config config\navigation_obstacle_validation.yaml --seconds 180 --output reports\navigation_obstacle.json`。测试立方体位于起点北侧 3 m、上方 3 m；航点先升至 3 m，再到北侧 6 m，最终回起点降落。结束后运行 `python scripts\navigation_test_obstacle.py --remove` 删除测试物体。脚本需要场景包含 AirSim 资产 `EditorCube`，不会修改现有场景对象。

## 可达性边界

“任意航点”指支持任意三维方向的航点输入，不代表障碍物内部、封闭区域或任意复杂迷宫都可达。当前使用滚动局部点云规划，没有全局地图或 SLAM；遮挡、稀疏光束和传感器盲区仍会影响避障。无局部路径、目标被占据、计算超预算、数据过期或缺采集时刻姿态时输出零速并报告原因。应调整航点、规划范围或场景后再继续，不会强行穿越障碍。

若出现 `3221225477` / `0xC0000005`，先找第一个退出的节点。2026-11-10 已从 Windows 应用日志确认多次故障模块为 `fastrtps-2.14.dll`，默认 DDS 改用 UDP 作为已实测的绕过方案；UE 共享内存采集不变。更新后重新激活全部相关终端，并重启 ROS/Foxglove/bag 节点。可在同一 ROS 域运行 `python scripts\diagnose_dds.py --domain 0 --seconds 60` 做不解锁的观察模式诊断，详细结果及限制见 [Fast DDS 崩溃排查与修复](FastDDS崩溃排查与修复.md)。更换 ROS 域可辅助隔离图，但不能视为中间件缺陷已根治。

本次完整 2K 双雷达负载下，固定步长仿真速度存在明显低于墙钟的情况。一次 60 秒全传感器验收中仿真时间约为墙钟的 0.50 倍，IMU 约 85.8 Hz，未通过原有 100 Hz/实时比例验收；该次导航雷达仍为较高的 460800 点/秒。最终导航雷达降为 230400 点/秒后，飞行与绕障需以实测记录为准，不能据此宣称全传感器性能指标已全部通过。不要更改真实时间戳或降低验收阈值来掩盖负载问题。
