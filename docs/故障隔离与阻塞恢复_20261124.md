# 评估故障隔离与阻塞恢复

本次只实施审核方案的第一、第二部分。未修改雷达应急与故障悬停的控制优先级。

## 原故障

`ros_20261123_194422_49a623` 在前往 `[0,80,10]` 时，定位误差评估节点保存
`summary.json` 遇到 Windows 拒绝访问而退出。管理器把评估进程也当作飞行关键依赖，
19:47:31 请求锁存 `failsafe_hold`，自机最终停在约 `[0,63.34,9.91]`。
此前 19:46:55 的 `goal_obstructed` 和后续雷达应急已恢复，非最终悬停原因。

## 修改后的故障处理

- 评估文件创建、追加、刷新、原子替换的 `OSError` 被隔离；实时误差曲线继续发布。
- 每个评估写入器使用独立临时文件。摘要保存失败按 0.5–5 s 有界退避重试，保留上一份摘要；
  文件恢复后保存最新统计。摘要被锁不会中断独立的误差逐行记录。
- 磁盘确实无法记录逐行数据时不无限缓存，`storage.dropped_rows` 明确计数；已丢失的行不会伪装成补录。
- `/drone1/localization/metrics.storage` 提供健康、错误、连续失败、丢弃行数和上次成功保存时间。
- 评估、目标真值、告警统计、轨迹显示、UE 检测框、未分类雷达诊断节点退出，仅告警并保留任务。
- 真值状态源下，独立定位估计及 GNSS/IMU/5G 节点退出不影响任务；融合状态源下按当前定位模式纳入关键依赖。
- 导航雷达、状态适配、安全控制、实际视觉融合依赖等关键进程异常仍使用现有故障保护；未知新节点默认关键。
- Foxglove 显示实际网关阶段、非关键进程告警、恢复原因和搜索半径；定位详情包含存储状态。

## 阻塞恢复

正常航段仍采样、2 Hz 规划、20 Hz 速度检查，不修改真实任务航点。

1. 距当前航点超过 1 m 时，沿原航段 3 s 净进展不足 0.5 m，且窗口内出现路径/障碍受阻证据，进入恢复。
   正常慢爬升不能只因进展计时而生成侧向绕行；参考通道畅通时优先重试原参考目标。
2. 正常采样点被挡时，先保留现有短时等待和安全制动。持续无进展才选临时绕行目标。
3. 在前方、左右、斜向、后方及允许的高度偏移中采样；优先可直接到达的出口，其次交给 A* 搜索。
   所有候选仍检查障碍膨胀净空；侧向和后退均允许，保持地面与原航段高度下界。
4. 临时目标保持一段时间，减少左右切换；端点被占据可改选。A* 仍检查完整路线，速度层继续检查运动预测。
5. 单次 6 s 未完成，切换候选并逐步扩大 6→10→14→15 m 搜索范围。总搜索计算预算不增加，工作进程数仍为 1。
   更大范围只使用新鲜实测融合目标；不引入仿真目标真值辅助规划。
6. 到达临时目标后回到原参考航段，继续原航点。恢复过程不会把临时点加入任务完成计数。
7. 无可用目标或路径时保持安全停止，明确报告 `blocked_no_recovery_goal` 等原因，并继续有限频率重试。
   不把“保持前进”置于碰撞检查之上。

恢复暂停/重置覆盖雷达应急与航点切换；传感器过期暂停无进展计时。
默认不在距目标 1 m 内触发恢复，避免正常终点减速被当成卡死。

## 配置与使用

`config/targeting.yaml` 的 `navigation.recovery` 提供设置（其他定位配置也有相同默认值）：

```yaml
navigation:
  recovery:
    enabled: true
    stalled_s: 3.0
    min_progress_m: 0.5
    arrival_exclusion_m: 1.0
    attempt_s: 6.0
    max_radius_m: 15.0
    radius_step_m: 4.0
    goal_tolerance_m: 0.6
    max_vertical_offset_m: 2.0
    switch_hold_s: 2.0
```

配置变更在下次启动 ROS 时生效。控制台保留这些底层配置生成本次运行快照，不覆盖用户的本地航点。
重新加载 Foxglove 面板后查看新状态。定位误差曲线保留三维、X、Y、Z 每曲线单行布局。

## 验证

自动回归覆盖 Windows 原生文件占用、解锁恢复、ROS 评估回调持续发布、非关键/关键节点分类、
侧向出口、后退脱困、封闭空间停止、扩大范围上限，以及占据采样点后绕行到原目的地的闭环。

UE 复验命令（先激活项目环境，确认无其他 UE 运行）：

```powershell
python .\tests\probe_flight_layers.py --case optional_failure --height 10 --seconds 160 --label optional_failure_check
python .\tests\probe_flight_layers.py --case blocked_sample --height 10 --seconds 90 --label blocked_sample_check
```

脚本仅管理自己创建的进程，使用隔离 ROS 域，结束后恢复会话原点，不覆盖用户的本地参数。
`optional_failure` 飞往 80 m 航点途中主动结束自有评估节点，检查告警、无锁存悬停且任务完成。
`blocked_sample` 用实际障碍机遮挡航段，检查绕行后的原目标到达和空中碰撞记录。
报告分别保存于 `reports/<label>/result.json`。

本版本仍是局部有限预算规划，持续密集封堵或感知失效时可能安全暂停；不会保证任意多机工况都可通行。
