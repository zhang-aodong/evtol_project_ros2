# Windows ROS 2 仿真功能包使用说明

## 1. 环境

当前电脑已安装 Windows 原生 ROS 2 Jazzy，依赖由 pixi 管理：

| 内容 | 路径或版本 |
|---|---|
| 操作系统 | Windows 11 x64 |
| ROS 2 | Jazzy，`C:\pixi_ws\ros2-windows` |
| Python | `C:\pixi_ws\.pixi\envs\default\python.exe`，3.12.3 |
| pixi | `%USERPROFILE%\.pixi\bin\pixi.exe` |
| 编译工具 | Visual Studio 2022 C++ x64 工具、Windows SDK |
| 仿真 | UE4.27 + 已编译的 AirSim 共享内存插件 |
| UE 工程 | `D:\Software\UEproject\MyProject 4.27\MyProject 4.27` |

本功能包不依赖旧的 Python 3.8 AirSim 环境，也不向 ROS Python 导入那个环境的 site-packages。RPC 适配器使用标准库实现 AirSim MessagePack-RPC 核心协议，避免旧 Tornado/msgpack-rpc 与 Python 3.12 的依赖冲突；NumPy 和 PyYAML 来自现有 ROS pixi 环境。

新电脑先按 [ROS Jazzy 官方 Windows 安装说明](https://docs.ros.org/en/jazzy/Installation/Windows-Install-Binary.html) 安装二进制包与其配套 pixi 依赖、Visual Studio C++ 工具，再将 `scripts/activate.ps1` 的 `PixiWorkspace` 和 `PixiExe` 参数指向实际目录。不要用 ROS Kilted/Rolling 的 Python 依赖替换 Jazzy 的固定依赖。

配置顺序是：安装 VS2022 的“使用 C++ 的桌面开发”、MSVC v143 x64、Windows SDK 和 VC++ 运行库；安装 pixi；下载对应的 Jazzy Windows 二进制包并解压到 `C:\pixi_ws\ros2-windows`；将 Jazzy 官方配套的 `pixi.toml` 放到 `C:\pixi_ws`，执行 `pixi install --manifest-path C:\pixi_ws\pixi.toml`；最后激活本工程并编译。当前验证组合包括 Python 3.12.3、NumPy 1.26.4、PyYAML 6.0.1、CMake 3.28.3 和 Qt 5.15.8。原始 Python 3.8 的 AirSim 虚拟环境无需参与本工程运行。

项目激活脚本默认使用 `evtol_bringup/config/fastdds_udp.xml`，ROS/DDS 仅使用 UDP。此配置用于绕过本机 Fast DDS 2.14.5 原生访问冲突；UE 相机及雷达的命名共享内存环继续使用。原 `fastdds.xml`（SHM + UDP）保留为对比配置，可在本终端用 `. .\scripts\activate.ps1 -DdsTransport shm` 显式切换；恢复使用 `-DdsTransport udp`。选择在当前进程环境中保留，不修改系统环境变量。旧终端原先自动加载的项目配置会随重新激活更新，外部自定义 DDS XML 默认保留，显式 `-DdsTransport` 可以覆盖。下游节点、Foxglove、RViz 和 bag 均应在相同激活环境、相同 ROS 域启动。实测和诊断步骤见 [Fast DDS 崩溃排查与修复](FastDDS崩溃排查与修复.md)。

每个新 PowerShell 都要执行：

```powershell
cd D:\ZAD_Files\evtol_files\evtol_project_ros2
. .\scripts\activate.ps1
python -c "import rclpy, numpy, yaml; print('environment OK')"
ros2 pkg list
```

若系统执行策略阻止项目脚本，可在本次终端中使用 `Set-ExecutionPolicy -Scope Process Bypass`，不必修改系统全局策略。脚本只设置当前进程环境。激活时设置 BLAS/OMP 单线程，避免六个传感器进程分别创建大型数值计算线程池。

## 2. 编译与测试

```powershell
.\scripts\build.ps1
. .\scripts\activate.ps1
.\scripts\test.ps1
```

`build.ps1` 自动定位 VS C++ 工具链，执行 `colcon build --merge-install`，使用 ROS 配套 Python 生成自定义消息的 C/C++/Python 类型支持。不需要管理员权限或 `--symlink-install`。`install/` 为合并安装目录，修改源码后必须重新编译并在新终端激活。

本机 colcon-output 的可选 summary 扩展与 colcon-core 版本不匹配；构建脚本只禁用该展示扩展，保留所有实际构建步骤。构建是否成功以退出码和四个功能包结果为准。

不启动 UE 的多进程 DDS 测试：

```powershell
python scripts\smoke.py --duration 60
```

此测试使用独立 ROS_DOMAIN_ID=73 和明确的 mock 数据，启动六个发布进程和一个订阅验收进程；结束时只关闭自己启动的进程树。结果为 `PASS_MOCK` 或 `FAIL`。生成的假图像、规则点云和理想时钟不代表 UE 传感器性能。

RViz2 启动、DDS 订阅、MCAP 录制与回放的自动检查：

```powershell
python scripts\check_tools.py
```

结果见 `reports/tools_acceptance.json`。该检查使用 mock 数据和独立域 74，检查 RViz 进程与显示订阅、全部话题写入和回放后重新收到数据；不代替图形界面的人工视觉检查或无损录制验收。

也可以手工运行 mock 并在 RViz 查看接口：

```powershell
ros2 launch evtol_bringup simulation.launch.py backend:=mock rviz:=true
```

## 3. AirSim 设置与插件

配置分为两个层次：

- `src/evtol_simulation/config/airsim.20hz.json`：UE 传感器生成参数；
- `src/evtol_simulation/config/simulation.yaml`：ROS 采集传输、频率、相机尺寸、标定和验收阈值；
- 同目录 `source_parameters.yaml`：源工程语义规则、GNSS 噪声、5G-A 基站和射频参数、场景轨迹。

本工程性能档明确将原工程双路 2K 图像改为双路 640×480；FOV=35°，相机 FRD 平移 `[0.3,0,0]`、俯仰 −10°，雷达 128 线、垂直 ±15°、水平 ±90°、100 m。LiDAR 设置 460800 points/s、`RotationsPerSecond=20`、`UpdateFrequency=20`。GPS/IMU/真值目标频率分别为 10/100/20 Hz。

`airsim.source_2k.json` 与 `simulation.source_2k.yaml` 保留原工程双路 2048×1536 图像尺寸，需成对使用并单独验收。两个档位均显式选择 `ClockType=ScalableClock`、`ClockSpeed=1`，让采集时间与墙钟推进一致；本机默认 SteppableClock 的实际 RTF 曾只有约 0.82。这不是确定性步进仿真，也不保证重负载下物理更新不会落后。确定性离线实验可用 SteppableClock，但实时吞吐应重新定义与测量。

本机可直接用项目配置启动离屏游戏，避免覆盖 Documents 下的全局设置：

```powershell
.\scripts\start_ue.ps1
# 或使用原分辨率：
.\scripts\start_ue.ps1 -Settings src\evtol_simulation\config\airsim.source_2k.json
```

脚本输出 UE 进程 PID 和日志路径。初次加载可能需要较长时间，等待 41451 端口就绪后再预检；不要同时启动另一个 UE 仿真占用该端口。需查看 UE 场景时使用编辑器 Play。以下替换全局 settings 的方式是另一个可选启动方法。

先关闭 UE，备份当前实际设置，再应用：

```powershell
$airsimDir = Join-Path $env:USERPROFILE 'Documents\AirSim'
$backupPath = Join-Path $airsimDir ('settings.before_ros2.' + (Get-Date -Format 'yyyyMMdd_HHmmss') + '.json')
Copy-Item -LiteralPath (Join-Path $airsimDir 'settings.json') -Destination $backupPath
Copy-Item -LiteralPath .\src\evtol_simulation\config\airsim.20hz.json -Destination (Join-Path $airsimDir 'settings.json')
```

重新打开 UE，进入 Play。设置模板按当前机场场景和 `Drone1`～`Drone7` 编写，其他场景需合并而非盲目覆盖。

共享内存使用源工程的同一协议：相机 `AS HM` magic 0x4D485341、8 槽 BGR8 环形缓冲；LiDAR magic 0x4D534C44、8 槽 XYZ float32，每槽最多 65536 点。相机启动/停止使用 `shm_push_start:<vehicle>:<camera>:<rate>` 和 `shm_push_stop:<vehicle>:<camera>` 控制 RPC。名称由 UE 启动响应返回；LiDAR 默认名称 `AirSimLidar_Lidar1`。

UE 插件必须已有相机主动推送、原生雷达共享内存和可配置 LiDAR 更新频率补丁。原版 AirSim 的雷达可能固定 10 Hz，增加 `UpdateFrequency` 键不会让未打补丁的插件自动支持 20 Hz。部署材料来自参考工程 `airsim_realtime_uav/patches/`，应由实际 UE 插件源码核对后编译；本工程没有自动覆盖外部 UE 源码。

编译实际 MyProject 插件示例（先关闭 UE）：

```powershell
& 'D:\Software\Epic\UE_4.27\Engine\Build\BatchFiles\Build.bat' `
  MyProjectEditor Win64 Development `
  '-Project=D:\Software\UEproject\MyProject 4.27\MyProject 4.27\MyProject.uproject' `
  -WaitMutex -NoHotReloadFromIDE
```

共享内存缺失时节点会报错、发布 ERROR 诊断，验收失败。若希望使用普通 AirSim，可将 `camera.transport` 和 `lidar.transport` 改为 `rpc`；这不会自动保证频率达标。RPC 图像需保持未压缩 BGR8 和 RGB/语义成批采集。

## 4. 真实仿真启动

在 UE 进入 Play 后运行：

```powershell
ros2 run evtol_simulation preflight --config src\evtol_simulation\config\simulation.yaml
ros2 launch evtol_bringup simulation.launch.py rviz:=true
```

预检通过 `getSettingsString` 检查运行中服务器实际加载的尺寸、FOV、传感器名称、外参和雷达频率；检查本地模板可使用 `--settings-file`，但离线预检不代表运行中的 UE 已应用设置。

采集节点另检查 `simGetCameraInfo.proj_mat` 的实际 SceneCapture 投影。AirSim 的 `fov` 字段可能来自预览相机，与传感器 CaptureSettings 不同，不能直接用它计算图像内参。

双路 2K 采集使用：

```powershell
ros2 run evtol_simulation preflight --config src\evtol_simulation\config\simulation.source_2k.yaml
ros2 launch evtol_bringup simulation.launch.py config:=src/evtol_simulation/config/simulation.source_2k.yaml rviz:=true
```

默认只采集，不移动载具。需要生成动态机场场景时：

```powershell
ros2 launch evtol_bringup simulation.launch.py rviz:=true scenario:=true
```

场景节点复用参考项目的配置：主机先爬升至 10 m，再沿初始机头前方飞 100 m，3 m/s；Drone2～Drone5 在前方 30/40/50/60 m 的配置点悬停；Pedestrian_2 按相对初始位置的折线移动。该节点执行固定实验轨迹，不执行源项目 avoidance 算法；感知、定位、建图和避障属于后续工作。启用场景前应确认机场地形和对象名称适合这些轨迹。

Ctrl+C 停止 launch；场景节点尝试取消自己的运动任务、降落、上锁和释放控制权。采集节点只停止自己启动的相机推送，不接管飞行。不要同时运行旧采集程序与新相机节点，以免双方竞争同一个 UE 主动流。

单独启动某组传感器进行排查：

```powershell
ros2 run evtol_simulation sensor_node --config src\evtol_simulation\config\simulation.yaml --kind imu
ros2 run evtol_simulation sensor_node --config src\evtol_simulation\config\simulation.yaml --kind lidar
```

`--kind` 支持 `camera/lidar/imu/gnss/truth/radio`。采集调度使用稳态墙钟，不依赖 `/clock` 启动，仿真暂停时去重并报告 stale。UE 重置时钟后需重新启动桥接，以免把跨场景数据混入同一时间轴。

## 5. ROS 接口

所有传感器使用 `SensorDataQoS`，即 Best Effort、Volatile、KeepLast(5)。这是有界的实时发布链路，验收测量订阅端实际收到的消息。`/diagnostics` 为 Reliable，`/tf_static` 为标准 TF Transient Local。下游 RViz、算法和 rosbag2 必须匹配 QoS。

| 话题 | 类型 | Hz | 内容 |
|---|---|---:|---|
| `/drone1/camera/rgb/image_raw` | sensor_msgs/Image | 20 | BGR8 |
| `/drone1/camera/rgb/camera_info` | sensor_msgs/CameraInfo | 20 | 当前尺寸/FOV 对应针孔内参 |
| `/drone1/camera/semantic/image` | sensor_msgs/Image | 20 | UE 调色板 BGR8 |
| `/drone1/camera/semantic/class_ids` | sensor_msgs/Image | 20 | mono8 类别 0～6，255 未知 |
| `/drone1/camera/semantic/camera_info` | sensor_msgs/CameraInfo | 20 | 与 RGB 对齐 |
| `/drone1/lidar/points` | sensor_msgs/PointCloud2 | 20 | FLOAT32 x/y/z/intensity |
| `/drone1/imu/data` | sensor_msgs/Imu | 100 | FLU 加速度/角速度、ENU 参考姿态 |
| `/drone1/gnss/fix` | sensor_msgs/NavSatFix | 10 | AirSim GPS 经纬高与质量 |
| `/drone1/gnss/raw_observations` | evtol_sim_interfaces/GnssObservations | 10 | 从真值合成伪距/相位/多普勒/SNR |
| `/drone1/five_ga/observations` | evtol_sim_interfaces/FiveGObservations | 10 | 六基站 PRS-RSRP、RTT、测距、LoS、有效标志 |
| `/drone1/ground_truth/odometry` | nav_msgs/Odometry | 20 | 独立仿真真值，供评估/调试 |
| `/clock` | rosgraph_msgs/Clock | 20 | 来自 AirSim 时钟 |
| `/tf`、`/tf_static` | tf2_msgs/TFMessage | 20/静态 | 真值显示与传感器外参 |
| `/diagnostics` | diagnostic_msgs/DiagnosticArray | 各节点 1 | 接收计数、源重复、错误、新鲜度、后端 |

intensity 延续源工程的常量占位 1.0，未模拟真实反射强度。源工程同射线 Actor ID 属于身份评估的插件辅助通道，本版没有将其作为传感器输入发布，也没有把真实 Actor 身份泄露给定位/建图算法。语义图是仿真真值，并非 YOLO 推理结果。

语义类别转换严格匹配原调色板的三个 BGR 分量，使用现有 ROS 环境的 OpenCV LUT 加速；颜色通道存在冲突或没有 OpenCV 时回退到完整颜色表，未知类别仍为 255。IMU 使用 Windows 高精度计时器控制发布周期，对旧 RPC 样本在本周期内重试；所有时间戳保持来自传感器，不插值、重打时间戳或补发旧样本。

5G-A 只生成观测，不运行旧工程的最小二乘求解器。GNSS 与 5G-A 消息的 `synthetic=true` 表示仿真生成，不区分 airsim 与 mock 后端；后端必须结合诊断检查。5G-A 无效链路可含 NaN 测距，必须先检查 `measurement_valid`。LoS 查询失败会报错，不默认当作无遮挡。

## 6. 时间和坐标系

世界 NED `[N,E,D]` 转 ENU `[E,N,-D]`；机体/传感器 FRD `[前,右,下]` 转 FLU `[前,左,上]`。四元数同时转换世界和机体基底，不能只更改四元数某个符号。

```text
map (ENU)
└── drone1/base_link (FLU)
    ├── drone1/camera_link
    │   └── drone1/camera_optical_frame (右、下、前)
    ├── drone1/lidar_link
    ├── drone1/imu_link
    └── drone1/gnss_link
```

默认 `map→base_link` 来自真值，仅用于仿真可视化。接入定位节点后将 `publish_truth_tf: false`，由定位节点独占该动态变换发布权；真值 Odometry 继续保留在评估话题。不要同时让真值和定位估计争用同一个 TF。

图像、雷达、IMU 和 GPS 直接保留传感器采集时间。RGB/语义必须具有完全相同的生产时间戳，启动时根据时间戳校准帧 ID 偏移。AirSim 真值 RPC 自身没有时间字段，使用 RPC 前后的 `getMultirotorState.timestamp` 中点估计采集时间，间隔超过 50 ms 即拒绝；这存在至多半个采样区间的不确定性，严格同步应用需在 UE 插件中原子输出真值及时间戳。

原始 GNSS 使用自己的真值采样时间；GPS fix 保留 GPS 自己的采样时间。AirSim GPS 默认有约 200 ms 输出延迟，两种观测属于独立采样流，不假装具有同一采集时刻，也不把延迟 GPS 的时间戳改写为当前时间。下游定位、建图和 RViz 设置 `use_sim_time=true`，使用 TF2 按消息时间查询变换，不用接收墙钟替代采集时刻。

## 7. RViz2 可视化

launch 参数 `rviz:=true` 自动加载 `evtol_bringup/rviz/simulation.rviz`。也可单独启动：

```powershell
rviz2 -d src\evtol_bringup\rviz\simulation.rviz --ros-args -p use_sim_time:=true
```

默认 Fixed Frame=`map`；已有 Grid、TF、LiDAR、RGB、语义图和真值 Odometry 显示。手工添加 PointCloud2/Image 时，将 Reliability 改为 **Best Effort**，Topic 选择上表相应名称。点云默认仅显示当前帧，没有把旧扫描直接叠加成未补偿的假地图。

RViz 的基础插件不会直接显示经纬度地图或完整 IMU 波形。IMU 姿态通过 TF/真值方向辅助查看，原始数值用 `ros2 topic echo`；GPS 数值用 NavSatFix 订阅，地理地图需要后续专用插件；GNSS/5G-A 自定义观测可通过 `ros2 topic echo` 查看。

典型调试命令：

```powershell
ros2 node list
ros2 topic list -t
ros2 topic hz /drone1/imu/data
ros2 topic hz /drone1/lidar/points
ros2 topic echo /diagnostics
ros2 topic echo /drone1/gnss/fix --once --qos-reliability best_effort
ros2 topic echo /drone1/five_ga/observations --once --qos-reliability best_effort
ros2 run tf2_ros tf2_echo map drone1/lidar_link
```

`topic hz` 是临时观察，不代替统一验收。图像/点云、RViz 和录包同时开启会增加负载，应在最终使用场景下重新验收。

## 8. 录制与回放

新 PowerShell 激活项目后运行：

```powershell
.\scripts\record.ps1
```

脚本按明确话题白名单录制 MCAP，包含 `/clock`、动态/静态 TF、诊断与所有传感器，自定义消息必须先在当前终端激活。按 Ctrl+C 正常停止，使 rosbag2 写完尾部索引和 metadata。异常终止的包不能当作已完成采集；支持的后端可尝试 `ros2 bag reindex`。

自动定时录制可用本机 rosbag2 的原生 Recorder API，正常关闭 writer：

```powershell
python scripts\record_for.py --output bags\timed_example --duration 10
```

duration 是启动 recorder 后等待的墙钟时长，最初发现阶段不一定有数据；目录必须尚不存在。`ros2 bag record --max-bag-duration` 是分包选项，不是录制结束时长。

检查及回放：

```powershell
ros2 bag info bags\sim_你的时间
ros2 bag play bags\sim_你的时间
```

先停止实时采集和场景节点，再回放。包已经包含原始 `/clock`，默认直接回放它，不同时追加 `--clock` 产生第二个时钟发布器。若特意录了不带 `/clock` 的包，再使用 `ros2 bag play ... --clock`。

修改 namespace 后同步调整 RViz 和 `bag_qos.yaml`、录包脚本白名单。默认原始图像未压缩，640×480 双彩色加 mono8 在 20 Hz 约 41 MiB/s，双路 2K 更高；磁盘吞吐和 DDS 丢帧必须实测。只读地图算法可用独立回放环境，与控制仿真分开。

## 9. 严格验收

在真实 UE 和发布节点运行时，另一个终端：

```powershell
.\scripts\validate.ps1 -Duration 60 -Warmup 10
# 原图像分辨率另行验收：
.\scripts\validate.ps1 -Duration 60 -Config src\evtol_simulation\config\simulation.source_2k.yaml
```

验收以订阅端唯一时间戳计数，所有默认传感器一起验收。通过标准：

- 20 Hz 话题 ≥19.5 Hz，100 Hz ≥97.5 Hz，10 Hz ≥9.75 Hz，且不高于目标的 110%；
- 仿真时间推进/墙钟推进 RTF 在 0.95～1.05；
- 仿真和接收时间最大帧间隔不超过四个周期；
- 不发布重复、逆序或零时间戳；源 RPC 重复轮询只在诊断中计数，不重复发布；
- 图像尺寸、编码、字节长度、语义 ID、点云字段与范围、IMU 四元数与有限数值、GPS fix、GNSS/5G-A 结构检查通过；
- 雷达不能为空；需要把载具放在可产生回波的位置；
- RGB/语义相同采集时间匹配率 ≥95%，相机/LiDAR 最近采集时间差 ≤50 ms；
- 六组诊断新鲜、后端为 airsim、无采集错误，并具备正确的动态/静态 TF。

退出码 0 才通过。结果包含每路目标/实际频率、样本数、RTF、最大间隔、空点云数与错误。`--allow-mock` 只生成 `PASS_MOCK`；不允许 mock 输入冒充真实验收。

也可让脚本负责启动和清理六个发布进程（UE 必须事先运行，不要同时手动 launch 同一组节点）：

```powershell
python scripts\smoke.py --backend airsim --duration 60
python scripts\smoke.py --backend airsim --duration 60 --config src\evtol_simulation\config\simulation.source_2k.yaml --report-prefix airsim_source_2k
```

自动检查使用独立域 73，完成后强制清理自己启动的进程树，适合测试；日常运行使用正常 launch/Ctrl+C，让节点执行清理。真实相机生产流可能在强制清理后仍留在 UE 中，停止 UE 会释放它。各配置实测和边界见 [验证记录](验证记录.md)。

常见失败：LiDAR 仍为 10 Hz→检查实际 settings 和插件更新频率；相机不足 20 Hz→检查 UE 渲染/GPU 回读和实际分辨率；IMU 不足 100 Hz→检查物理源更新，不能把旧样本重发成新样本；语义规则未匹配→按当前资源 Mesh 名称修改 `source_parameters.yaml`；点云不可见→检查 `SensorLocalFrame`、TF、FOV 和 RViz QoS。

## 10. 后续定位/建图接口

后续包订阅 `/drone1/imu/data`、`/drone1/lidar/points`、图像与 CameraInfo、GPS 或原始无线观测；发布 `/drone1/localization/odometry`、地图、规划等独立话题。真值数据只能用于明确标记的评估/对照。仿真包不得导入定位/建图实现，定位/建图算法也不应直接读取 Windows 共享内存或 AirSim RPC。
