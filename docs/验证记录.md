# 本机验证记录

日期：2026-11-04。环境：Windows 11、原生 ROS 2 Jazzy、Python 3.12.3、Visual Studio 2022；UE4.27 MyProject 机场场景及现有 AirSim 插件。参考工程为 `evtol_project/airsim_realtime_uav`。

## 验证范围

四个功能包已在本机完成 colcon 原生编译，包括自定义消息的 C/C++/Python 类型支持。协议、坐标转换、观测模型、Windows 命名共享内存、调度重试、精确语义转换和失败验收分支共 20 项单元测试通过。

验收不是对发布函数调用次数计数，而是独立 ROS 进程订阅唯一采集时间戳，检查数据内容、墙钟频率、RTF、最大间隔、RGB/语义配对、相机/雷达时间差、TF 与六组运行诊断。20/100/10 Hz 的最低接收频率分别为 19.5/97.5/9.75 Hz；没有放宽阈值来让 2K 通过。

以下数据为机场场景静止采集、六组真实传感器同时运行、12 秒预热后连续 60 秒测量；不包含可选场景任务、RViz 和录包的共同负载。开启这些消费者或飞行后应重新验收。

## 运行边界

没有替换用户 Documents 下的 AirSim 全局设置，也没有修改、重新编译外部 UE 插件。验证使用 `start_ue.ps1` 相同的 `-game -RenderOffscreen -settings=<项目配置>` 启动方式。仿真器初次加载耗时较长，不能仅凭进程出现就启动验收，应先通过运行时预检。

GPS fix 保留原生约 200 ms 延迟的采集时间；GNSS 原始观测采用自己对应的真值采样时间。相机根据实际采集投影矩阵校验标定，避免将预览 FOV 当成传感器 FOV。ScalableClock 用于实时数据采集，不提供确定性物理步进保证。

可选 `evtol_scenario` 已按参考配置迁移固定主机路径、障碍机和行人逻辑，尚未完成运动任务验收，默认关闭；定位、建图、感知推理和避障没有作为传感器节点的一部分运行。源工程 Actor ID 身份评估辅助通道也未作为物理传感器发布。

复测命令、分辨率切换、环境配置、录制和 RViz 使用方法见 [功能包使用说明](功能包使用说明.md)。
